2三个角色到底是什么

💡 桌面类比：Context 是桌面，Agent 是坐在桌前的人，Skill 是抽屉里的手册

桌面（Context）上摆什么，人（Agent）就能看见什么；手册（Skill）平时收在抽屉里，需要时翻开放上桌面。

上下文决定 Agent 的三个边界：

知道什么系统提示、记忆、检索结果不在上下文里 = 不存在
能做什么工具 schema 不进上下文 = 调不到；进了 = 每轮付费
怎么做Skill、约束、示例都在上下文里塑造行为

4Skill 如何沉淀可复用知识（重点二）

先分清两种知识——这决定它们该存哪：

陈述性知识程序性知识
是什么"知道"的事实、偏好、背景"会做"的流程、检查清单
该存哪Memory（记忆文件）Skill（技能文件夹）
例子用户在城市 X、用 Python同步 GitHub 要先对齐 SHA
💡 Skill 与 Context 的配合正是"省着用"的关键

Skill 三层渐进披露（元数据常驻 → 指令按需 → 脚本不进上下文）本质上就是一套上下文预算管理方案。

6记住这几点

✅ 记忆锚点

  • 关系链：Skill（静态文件）→ 注入 Context（动态台面）→ 驱动 Agent（运行循环）→ 经验回流 Skill
  • Context 管边界：不在上下文里的工具/知识，对 Agent 等于不存在
  • 上下文只增不减：四种病（丢失/稀释/溢出/烧钱）都从这里来
  • 两种知识分家：事实进 Memory，流程进 Skill
  • 沉淀闭环：执行 → 提炼 → 写入 → 触发 → 修正，个人经验变组织资产

7五道测试题（点开看答案）

① 三者关系链中，Context 的角色是？

✅ 动态工作台面——模型此刻"看得见"的全部输入信息。Skill 是收在抽屉里的手册，Agent 是坐在桌前的人，Context 是桌面

② Skill 注入 Context 的根本目的是？

✅ 让 Agent 知道"这件事该怎么做"——把程序性经验送上工作台面，否则 Agent 看不见就不会用

③ 上下文"只增不减"会引发"四病"，不包括？

✅ 训练数据污染（其余都是：信息丢失 / 注意力稀释 / 窗口溢出 / 成本失控）

④ 沉淀 Skill 的正确流程是？

✅ 执行 → 提炼 → 写入 → 触发 → 修正，让个人经验变成可复用的组织资产

⑤ "Agent 上限由模型决定，下限由上下文工程决定"——下限由什么决定？

✅ 上下文工程（送什么进模型、怎么组织），这是 Agent 时代真正可工程化提升的部分
