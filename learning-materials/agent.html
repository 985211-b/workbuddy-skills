Agent 智能体

会自己干活的 AI，不是只会回答的 AI

① 是什么② 怎么运作③ 真实案例④ 常见误区⑤ 记住这几点
Agent = 给它一个目标，它自己「拆任务 → 调工具 → 看结果 → 再修正」，循环往复直到完成，全程不用你一步步指挥。

1是什么

一个公式就够了：Agent = LLM（大脑）+ 规划 + 记忆 + 工具

🧠LLM 大脑

思考"现在该干嘛"

📋规划

拆任务、排顺序、中途改计划

💾记忆

记住干过什么

🔧工具

搜索、代码、API……手和脚

🔁循环

边干边想，不是一次答完

🤔判断标准

能根据中间结果自己改下一步的，才是真 Agent

和聊天机器人的区别：调一次工具就结束的叫函数调用；有循环、能改计划的才叫 Agent。每步都写死的叫工作流（Workflow）。

2怎么运作

决定 Agent 质量的关键（点开看）

往往不是模型本身，而是循环和工具的设计——平庸模型 + 好的工具接口，胜过顶级模型 + 糟糕的脚手架。复杂任务可升级为"先列完整计划再执行"（Plan-and-Execute）或"干完自我批评再重试"（Reflexion）。MCP 协议正在成为工具接入的"USB 接口"标准。行业最新共识：从"全自治"回归"可控"，关键动作人类审批（Human-in-the-loop）是生产标配。

3真实案例

场景：40 人后端团队引入编程 Agent（Claude Code / Cursor 类）。

四步落地法
步骤做法
① 低风险起步先干容易回滚的活：补单测、写 mock、修文档
② 观察循环Agent 自主"读模块 → 找缺口 → 写测试 → 跑 → 失败自己修（最多 2 次）"，人只审最终 diff
③ 分级授权可逆动作放行；push 主干、合并 PR、改生产配置 → 强制人工审批
④ 逐步扩大稳定后再碰文件迁移（业内实测比人工快约 10 倍）

效果：Rakuten 功能交付周期缩短约 79%；NVIDIA 3 万开发者代码提交量约 3 倍。翻车点：剪掉代码评审换吞吐量。

4常见误区

❌ 多智能体一定更强

数据不支持：多数基准提升有限，还带来辩论死循环、互相推诿。需不需要看三点——有无不确定性分支、是否需对抗审查、是否需多领域知识，都不满足就用简单流程。

❌ 越自主越好

最危险。Replit Agent 曾无人监管下删掉生产库 1206 条记录；OWASP 已把"过度自主权"列入 AI 十大漏洞。自主性必须配可控性。

❌ 它能承担责任 / 保证正确

不能。Air Canada 案确立：Agent 的错误承诺责任归部署公司。幻觉在 Agent 里会从"说错话"升级为"做错事"，生产必须配溯源 + 输出校验。

5记住这几点

✅ 记忆锚点

  • 公式：Agent = LLM + 规划 + 记忆 + 工具，灵魂是"循环 + 动态决策"
  • 质量：决定成败的往往是脚手架设计，不是模型
  • 生产铁律：不可逆动作必须人类审批
  • 头号风险：提示词注入——指令和数据分不清，别在不可信环境给高权限

7五道测试题（点开看答案）

① Agent 的核心循环是？

✅ 感知 → 思考（推理 / 规划）→ 行动（调工具）→ 观察结果 → 回到感知，循环往复

② Agent 的"下限"主要由什么决定？

✅ 上下文工程（送什么进模型、怎么组织）。上限才是模型本身的能力，下限由你给的上下文质量托底

③ ReAct 框架中 "Re" 与 "Act" 分别是？

✅ Reasoning（推理：决定下一步做什么）+ Acting（执行：调工具或输出）。先想再干，干完再想

④ 哪一项不是 Agent 的典型组件？

✅ 训练数据集（其余都是：LLM 大脑、工具调用、记忆系统、规划 / 反思能力）

⑤ 多 Agent 协作相对单 Agent 的核心价值是？

✅ 分工 + 辩论 + 互相监督：把复杂任务拆细并交叉校验，提升可靠性与质量上限
